## Phase 2 Discoveries

### New Ownership Claims

```
CLAIM: Error taxonomy (shared/errors.py — AtlasError hierarchy, ErrorCategory, ErrorSeverity)
OWNER: Volume 8
REASON: Error hierarchy is API infrastructure. All subsystems consume AtlasError subclasses, but Vol 8 defines the base class, category/severity enums, and HTTP status mapping. Per PROJECT_CONVENTIONS.md Section 6.
CONTESTED: no
```

```
CLAIM: Configuration schema (shared/config.py — AtlasConfig)
OWNER: Volume 8
REASON: Server configuration including port, host, CORS, feature flags, and timeout overrides. All subsystem config values live in AtlasConfig. Per PROJECT_CONVENTIONS.md Section 8.
CONTESTED: no
```

```
CLAIM: API contract schemas (contracts/api_schemas.py — ChatRequest, ChatResponse, ErrorResponse, HealthResponse, StreamEvent)
OWNER: Volume 8
REASON: HTTP-boundary Pydantic schemas that define the API↔Console contract. Vol 8 owns these schemas and the TypeScript codegen that produces Console types from them. Per shared-contracts.md Section 1.3.
CONTESTED: no
```

```
CLAIM: TypeScript codegen script (contracts/generate_ts_types.py)
OWNER: Volume 8
REASON: Per conflict resolution C-11. Vol 8 generates TS interfaces from Pydantic models for Console consumption. Vol 7 consumes the output but does not own the generation.
CONTESTED: no
```

```
CLAIM: Middleware stack (api/middleware.py — RequestLogging, Timeout, ExceptionHandler)
OWNER: Volume 8
REASON: HTTP middleware is API infrastructure. The three-middleware pattern from Attempt 3 is preserved with improvements (structlog, configurable timeouts, no circuit breaker).
CONTESTED: no
```

### Conflict Resolutions Applied (from gate-output/conflict-report.md)

- **C-10 (resolved):** Endpoint prefix is `/v1/*` canonical. Applied in B.3 and B.4.
- **C-11 (resolved):** TS codegen owned by Vol 8. Claimed above.
- **C-12 (resolved):** Single `POST /v1/atlas/chat` with `stream: bool` field. No separate `/stream` path. Applied in B.6 (ChatRequest.stream field) and B.8 (AT-API-04).
- **C-13 (resolved):** ConversationResponse→ChatResponse mapping is Vol 8's responsibility. `response`→`answer`, `evidence_refs`→`evidence`. Applied in B.6.
- **C-16 (resolved):** Errors at `shared/errors.py`. Applied in B.7.
- **C-17 (resolved):** Field is `query` not `message`. Applied in B.6 (ChatRequest.query).

### Phase 2 Risks Identified

1. **aiosqlite migration (B.11 item 4):** Attempt 3 has raw `sqlite3.connect()` calls in route handlers. Vol 1 (Memory) owns the async SQLite wrapper, but Vol 8 must verify no route handler touches SQLite directly.
2. **Single-endpoint streaming (B.11 item 3):** Merging JSON and SSE responses into one endpoint requires content negotiation in the route handler. AT-API-04 covers this.
